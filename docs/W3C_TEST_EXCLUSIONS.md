# W3C Test Exclusions and Conformance Rationales

W3C conformance tests are executed by default. In accordance with W3C EARL 1.0 and ISO/IEC 29119 testing standards, no test is skipped silently. Every excluded or non-passing test is documented below with its exact manifest identifier, rationale, and reactivation condition.

## Inapplicable Tests

Tests covering specification features intentionally unsupported because they fall outside the Corese conformance profile (`earl:inapplicable`).

### JSON-LD 1.1: Generalized RDF Blank-Node Predicates

Under RDF 1.1 Concepts and Abstract Syntax (§3.1), predicates in RDF triples MUST be IRIs, not blank nodes. The JSON-LD 1.1 flag `produceGeneralizedRdf` emits blank-node predicates, which cannot be represented in standard RDF 1.1 triples.

| Direction | Test ID | Feature | Specification Reference | Reason | Reactivation condition |
| :--- | :--- | :--- | :--- | :--- | :--- |
| toRdf | `t0118` | produceGeneralizedRdf | JSON-LD 1.1 Processing Algorithms §4.1.2 | `produceGeneralizedRdf` emits blank-node predicates. | Corese adds support for generalized RDF graphs. |
| toRdf | `te075` | produceGeneralizedRdf | JSON-LD 1.1 Processing Algorithms §4.1.2 | A blank-node `@vocab` produces blank-node predicates. | Corese adds support for generalized RDF graphs. |

### SPARQL 1.1: Unapproved Draft Contradicting Specification

Under SPARQL 1.1 Query Language (§18.5.1.3), `AVG` over an empty group evaluates to an error (`undef`), not `0`. Test `agg-avg-03` is an obsolete draft lacking `dawgt:approval` that contradicts the normative W3C Recommendation.

| Test ID | Feature | Specification Reference | Reason | Reactivation condition |
| :--- | :--- | :--- | :--- | :--- |
| `agg-avg-03` | AVG empty group | SPARQL 1.1 Query §18.5.1.3 | Test lacks `dawgt:approval` and expects `0` instead of `undef`. | Upstream suite either approves or removes the test. |

## Untested Tests

Tests applicable to Corese but excluded from automated execution runs due to isolated upstream dependency edge-cases (`earl:untested`).

### RDFa Composite Fixture Exclusions

Test `0295` concatenates bodies of independent test documents, but its expected graph is the union of results parsed separately. Concatenation is not semantics-neutral in RDFa (initial contexts and list mappings are scoped by the surrounding document).

| Host | Test ID | Classification | Reactivation condition |
| :--- | :--- | :--- | :--- |
| XHTML | `0295` | Composite-fixture semantics | Expected output regenerated by parsing concatenated document. |
| XML | `0295` | Composite-fixture host mismatch | Fixture stops applying HTML-only rules and honors XML base. |
| SVG | `0295` | Composite-fixture host mismatch | Fixture stops applying HTML-only rules and honors XML base. |

## Indeterminate Tests

Actively executed tests producing an indeterminate verdict due to documented discrepancies in upstream manifest expectations (`earl:cantTell`).

### SPARQL 1.1: cast-decimal

- **Test IRI**: `http://www.w3.org/2009/sparql/docs/tests/data-sparql11/cast/manifest#cast-decimal`
- **Specification Reference**: SPARQL 1.1 Query Language §17.4.3.1 (`xsd:decimal`)
- **Reason**: The official manifest expected result table rewrites the unmodified source binding `?v` for `n07`–`n10` from `0E1`/`1E0` to `0.0`/`1.0` (double and float).
- **Classification**: Only this exact four-binding discrepancy is reported as EARL `cantTell`, not `passed`, `inapplicable`, or `untested`. All 31 rows and every other binding agree.
- **Reactivation condition**: Upstream manifest preserves the source lexical forms or clarifies the comparison rule.
